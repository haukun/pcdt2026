# SPEC.md 整合性ルール

このプロジェクトの正となる仕様書は `viewer/SPEC.md`。
PreviewViewer に関する変更・修正・追加を行ったときは、**必ず `viewer/SPEC.md` と整合を取る**こと。

## 必須ルール

- コードやデータ構造・運用ルールを変更・修正・追加したら、同じ作業の中で `viewer/SPEC.md` の
  該当節を更新する。変更とドキュメント更新はセットで完了とみなす（SPEC 更新を省略しない）。
- 更新対象の主な節:
  - 設定定数（再生時間・文字数上限・タイピング速度など）を変えたら → 「4. 設定定数」の表
  - 再生ロジック・iframe実行・配置・postMessage を変えたら → 「4. 再生ロジック」
  - カードの構成・タイピング・カウンター・演出を変えたら → 「5. Twitter風カード」
  - manifest のスキーマ・生成ルール・命名/日付規約を変えたら → 「3. manifest 生成」
  - `.gitignore` / jj / 管理対象を変えたら → 「8. バージョン管理」
  - 制約や積み残しが増減したら → 「7. 既知の制約・今後の検討事項」
- 上記に加え、大きめの変更は「9. 変更履歴」に1行追記する。

## 整合性チェック

- 作業の区切りで、SPEC.md の記述と実際のコード（`viewer/player.js` / `build-manifest.mjs`
  / `index.html` / `style.css`）に食い違いがないか確認する。
- 食い違いを見つけたら、実装を正としてドキュメントを直すか、意図した仕様なら実装を直すか、
  どちらが正しいかを判断して合わせる（放置しない）。

## 参照

- 何かを分析・拡張する前に、まず `viewer/SPEC.md` を読んで現状仕様を把握してから着手する。
